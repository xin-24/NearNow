# Demo 脚本

## 1. 演示目标

展示本地短时活动规划与执行 Agent 如何从一句自然语言中完成理解、规划、工具调用、用户确认和自动执行。

Demo 默认使用 Mock Provider。后续真实模式演示需要替换为真实 Geo、POI、Merchant 和 Route Provider，并保证输出真实地理位置、真实店铺名称和真实交通路线。

## 2. 正常场景

### 2.1 用户输入

```text
今天下午是空的，想和老婆孩子、朋友出去玩几个小时，别离家太远，帮我安排一下。
```

### 2.2 Agent 内部动作

```text
1. 解析出时间：今天下午，默认 14:00-18:00。
2. 解析出参与人：小明、老婆、5 岁孩子、4 位朋友。
3. 解析出偏好：附近、亲子友好、朋友可参与、晚饭适合减脂。
4. 查询附近活动。
5. 查询活动余位。
6. 查询附近餐厅。
7. 查询餐厅座位和排队情况。
8. 生成可执行方案。
9. 等待用户确认。
```

### 2.3 Agent 输出

```text
我给你安排了一条不折腾、适合孩子和朋友一起参与的路线：

14:00 从家出发，建议驾车或网约车
14:20-15:40 城市亲子探索馆
15:40-16:00 步行到周末生活市集
16:00-16:50 逛市集和小吃街
17:10-18:00 绿野轻食融合菜晚餐

这条路线控制在家附近 6 公里内。第一段驾车约 20 分钟，商场内两段步行均在 5 分钟内。亲子探索馆适合 5 岁孩子，市集适合朋友一起逛，晚餐有 7 人桌，也有轻食和低脂菜。

你确认后，我会帮你完成：
1. 预约城市亲子探索馆 7 人名额
2. 预订 17:10 绿野轻食融合菜 7 人桌
3. 把计划发给小张
```

### 2.4 用户确认

```text
确认，安排吧。
```

### 2.5 执行结果

```text
搞定了：

1. 城市亲子探索馆预约成功，确认号 A20260511001
2. 绿野轻食融合菜 17:10 订座成功，确认号 R20260511001
3. 已把计划发给小张

下午 2 点从家出发即可。
```

## 3. 异常场景一：餐厅无位

### 输入

```text
下午想带老婆孩子和朋友出去玩，晚上找个适合减脂的餐厅。
```

### Mock 条件

首选餐厅 `绿野轻食融合菜` 无可用桌位。

### 期望输出

```text
首选的绿野轻食融合菜 17:10 已经没有 7 人桌。我帮你换成同商场的清禾小馆，17:20 有 8 人桌，步行只多 3 分钟，也有低脂套餐。

确认后我会预订清禾小馆，并保留原活动安排。
```

## 4. 异常场景二：活动满员

### 输入

```text
今天下午想找个适合 5 岁孩子，也能和朋友一起玩的地方。
```

### Mock 条件

首选活动 `城市亲子探索馆` 剩余名额为 0。

### 期望输出

```text
城市亲子探索馆今天下午已满。我换成了同区域的儿童科学工坊，14:30 还有 10 个名额，适合 4-8 岁孩子，朋友也能参与互动。
```

## 5. 异常场景三：缺少出发地

### 输入

```text
下午帮我安排一个附近的亲子活动和晚饭。
```

### Mock 条件

请求上下文没有 `home_location`。

### 期望输出

```text
可以，我需要先知道从哪里出发，才能控制距离和路线。你想从家、公司，还是某个具体地点出发？
```

## 6. 演示检查清单

- 能看到自然语言输入。
- 能看到 Agent 生成时间轴方案。
- 能看到每段路线的交通方式和预计耗时。
- 能看到待确认动作。
- 用户确认前没有执行预约和订座。
- 用户确认后能看到每个动作的执行结果。
- 异常场景能给出可恢复方案。

## 7. 真实模式演示要求

真实模式演示应满足：

- 用户授权定位或输入真实出发地址。
- 活动地点和餐厅名称来自真实 Provider，不使用 Mock 名称。
- 每个地点包含真实地址和经纬度。
- 至少比较两种交通方式，例如驾车和公共交通。
- 最终方案说明为什么选择某种交通方式，例如同行者便利性、耗时更短、少换乘、停车方便、宠物可乘坐。
- Provider 失败时展示降级策略，例如切换手动输入地址或换用备选交通方式。
